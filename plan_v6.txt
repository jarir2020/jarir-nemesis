PHASE 9 — Malicious Shell Upload Scanner & Immobilizer  [NEW]
================================================================
Status: Missing entirely. Critical for any framework accepting
        file uploads.
Goal:   Detect and neutralize uploaded webshells and malware.

Deliverables:
  - ShellScanner: scans uploaded files BEFORE they are saved
  - Signature database (patterns): eval(base64_decode), system(),
    exec(), passthru(), shell_exec(), popen(), proc_open(),
    $_REQUEST/$_GET/$_POST used as code, obfuscated PHP tags,
    <?php combined with base64/gzinflate/str_rot13 chains
  - Entropy analysis: high-entropy strings often indicate
    obfuscated shells (Shannon entropy threshold, configurable)
  - MIME type double-check: verify real MIME vs extension
    (finfo_file), reject PHP disguised as image/pdf
  - Immobilizer actions (configurable, in order):
      1. BLOCK  — reject the upload, return 422
      2. QUARANTINE — move to storage/quarantine/ (not web-accessible)
      3. DEFANG — rename to .suspected, strip execute permission
      4. ALERT  — fire ShellUploadDetected event → Notification
  - ShellScanMiddleware: wraps UploadedFile before it reaches
    controllers (opt-in per route or global)
  - `php nemesis security:scan {path}` — scan existing files on disk
  - Config: config/security.php — entropy threshold, blocked
    extensions, quarantine path, alert channels
  - Hooks: ShellDetected event → log + notify admin

PHASE 10 — DDoS Detection + Traffic Redirection           [NEW]
================================================================
Status: Missing entirely. No rate-limit intelligence, no
        automatic IP blocking, no attacker redirection.
Goal:   Detect HTTP-layer DDoS, block IPs, redirect attackers
        to high-capacity sinks to exhaust their bandwidth.

Deliverables:

  A. DETECTION
  - Request rate tracking per IP (sliding window, Redis or file)
  - Configurable thresholds (per second, per minute, per hour)
  - Suspicious pattern detection:
      - Same IP, high request rate
      - Unusual User-Agent patterns (empty, known bot strings)
      - Repetitive identical requests (hash-based dedup)
      - Distributed detection: track subnet (/24) as a group
  - Scoring system: each signal adds a threat score; above
    threshold triggers action

  B. ACTIONS (ordered by severity, configurable)
  - RATE_LIMIT  — slow down (429 with Retry-After header)
  - CAPTCHA     — redirect to challenge page (Phase TBD)
  - BLOCK       — add IP to blocklist, return 403
  - REDIRECT    — redirect attacker to bandwidth sink (see below)

  C. BANDWIDTH SINK REDIRECTION
  Redirect detected attackers to public Hetzner speed test servers.
  These are legal, public endpoints designed for high-throughput
  and can absorb the attack traffic, exhausting the attacker's
  bandwidth:

      https://nbg1-speed.hetzner.com/10GB.bin  (Nuremberg)
      https://fsn1-speed.hetzner.com/10GB.bin  (Falkenstein)
      https://hel1-speed.hetzner.com/10GB.bin  (Helsinki)
      https://ash-speed.hetzner.com/10GB.bin   (Ashburn, VA)
      https://hil-speed.hetzner.com/10GB.bin   (Hillsboro, OR)
      https://sin-speed.hetzner.com/10GB.bin   (Singapore)

  Sink selection: round-robin or geo-closest (by IP geolocation).
  Response: HTTP 302 to selected sink URL.
  Note: effective against HTTP-layer (L7) attacks where the
  attacker's client follows redirects. Does NOT stop SYN floods
  or UDP floods (those require firewall/upstream mitigation).

  D. IP BLOCKLIST
  - Persistent blocklist: Redis (TTL) or DB (expires_at)
  - Auto-expire blocks after configurable duration
  - `php nemesis ddos:blocklist` — view current blocked IPs
  - `php nemesis ddos:unblock {ip}` — manually unblock
  - `php nemesis ddos:stats` — request rates, top IPs, blocked count
  - Webhook: fire DDoSDetected event → Slack/email notification

  E. CONFIG (config/ddos.php)
  - enabled: bool
  - thresholds: [per_second: 20, per_minute: 200, per_hour: 1000]
  - action: rate_limit | block | redirect
  - sink_urls: array of Hetzner URLs
  - sink_strategy: round_robin | geo_closest
  - block_ttl: 3600 (seconds)
  - whitelist: [127.0.0.1, ::1, your office IP]

  Cannot be implemented within a PHP framework. SKIP.

  Cannot be implemented within a PHP framework. SKIP.

================================================================

  and pass stdout back as HTTP response. Requires Perl installed
  on server. Very niche use case. Defer to optional plugin.
